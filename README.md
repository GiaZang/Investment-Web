**面向个人投资者的 AI 财报速读与风险预警 Agent：把一份季报变成 3 分钟能读完的结论清单，每一条都能点回原文那一行。**

## 一、产品选择

### 目标用户

**自己管钱的个人投资者**：持有 10–30 只标的，看得懂 PE 和营收增速，但没有时间逐页读财报。季报季（4 月、8 月、10 月）一周内会涌进 10 份以上 PDF，每份 60–120 页。

### 真实工作流

> 季报披露 → 打开产品选标的 → 3 分钟读完结论 → 对不放心的数字点「查看原文」核到 PDF 第几页第几个字符 → 看风险雷达有没有该问公司的解释 → 导出底稿存档

### 痛点

1. **读不完**：一份季报 100 页，真正影响判断的只有「主要会计数据」+「报表项目变动原因」两处，但要先读到才能知道。
2. **读不懂关联**：营收 +36.94%、利润 +78.65%，差 41.71pct 是怎么来的？公司说"库存储备增加"，这是好事还是坏事？
3. **不敢信 AI**：让大模型总结财报，它会编数字、把别家公司的数据当成这家的，而且看不出错。

### 非目标（明确不做）

| 不做 | 原因 |
|---|---|
| 选股、估值、买卖建议、目标价 | 证券投资咨询需持牌；产品定位是「读得更快更准」，不是「替你决策」 |
| 涨跌预测、收益承诺 | 题目统一规则明令禁止 |
| 判定财务造假、舞弊 | 需审计与司法认定，产品只提示「该指标偏离常规区间，建议人工复核」 |
| 行业横向排名结论 | 只并列已披露数字与公司自述原因，不生成"谁更好"的判断 |
| 组合管理、盯盘、交易 | 与「读财报」不是同一件事，做进来会稀释主链路 |

### 成功标准（可衡量）

| 标准 | 目标 | 实测 |
|---|---|---|
| 单份财报出结论耗时 | < 10 秒 | **9 ms（p50，20 次）** |
| 结论可追溯率（带原文引文的结论占比） | 100% | **100%（9/9）** |
| 无出处结论数 | 0 | **0**（无引文的条目在代码层不生成） |
| 数据缺失时是否静默给"正常" | 否 | **否**，降级为「无法判断」（新易盛 7 条规则全部 INSUFFICIENT） |

## 二、为什么必须是 Agent，而不是规则 / 搜索 / 传统数据产品 / 人工

| 方案 | 能做什么 | 做不到什么 |
|---|---|---|
| **纯规则** | 数字算得准、可复现（本产品 7 条风险规则全是纯规则） | 读不懂非结构化文本：找不到"存货变动原因"那句话，也无法把一段券商式表述改写成中文 |
| **纯搜索/RAG** | 能定位到相关段落 | 给不出结论。搜到"存货 121.10 亿"和"主要系库存储备增加"之后，仍需人判断这两句意味着什么 |
| **传统数据产品**（行情终端、财务数据库） | 结构化字段齐全、准确 | 只给数字不给判断：不告诉你 110.76% 的存货增速相对 36.94% 的营收增速意味着什么，也不并列公司自己的解释 |
| **人工** | 判断质量最高 | 一篇 30–40 分钟，季报季读不完，且不留痕、不可复现 |
| **本产品** | 结构化事实（规则） + 长文本定位（解析） + 措辞生成（LLM）三者分工，且判定权归规则 | 不覆盖未建卡的科目（如毛利率），此时明确说"未覆盖"而不是猜 |

**关键取舍：AI 只做它擅长的两件事，判断权不交给它。**

| 环节 | 谁做 | 为什么 |
|---|---|---|
| 数字抽取与计算 | 确定性代码（正则 + 单位归一 + 量级门禁） | LLM 算数不可靠，且错一位小数就毁掉整篇结论 |
| 规则是否命中 | 阈值比较（纯函数） | 可复现、可复算、可被审计 |
| 长文本理解（"公司怎么解释存货增加"） | PDF 文本层定位 + 引文摘录 | 需要理解语义，但结果必须是原文片段 |
| 措辞改写、自由问答 | LLM（可选） | 这是 LLM 真正不可替代的部分；输出必须过数字白名单 |
| 最终是否采信 | 人（点「查看原文」） | 产品交付的是"可核对的底稿"，不是"代替你判断" |

## 三、核心工作流与 AI 的角色

```
选标的 → 载入事实卡（含原文引文/偏移/披露日）
      → 生成结论（无引文不生成）
      → 利润归因（只用两期原值）
      → 风险雷达（7 条规则，命中即并列公司自述原因）
      → 问答 / 改写（可选 LLM，过数字白名单 + 合规词表）
      → 导出底稿（.md，含出处与免责）
```

### AI 参与的三处，以及各自的边界

| # | 参与点 | 输入 | 输出 | 校验 | 失败时 |
|---|---|---|---|---|---|
| 1 | 摘要改写 | 模板结论（含数字） | 更通顺的中文 | 数字白名单 + 合规词表 | 丢弃 AI 文本，**回退模板**并告知哪串数字没过 |
| 2 | 自由问答 | 检索到的原文块 | 带 `[n]` 引用的回答 | 同上；无引文块时直接拒答 | 改用原文摘录 |
| 3 | 指标归类候选 | 一句话 | "这句在说哪个指标" | **候选必须回事实卡重新核算**，算不上仍判未知 | 视为未找到出处 |

> 第 3 点是最容易被忽略的设计：LLM 说"这句在讲存货"只是候选，真正的判定仍发生在规则层。**关掉 LLM，四条 Tab 的结论一条都不会变**——这是"AI 不参与判定"的可验证证据。

### System Prompt（原文，见 `app.py:SYSTEM_PROMPT`）

```
你是 FinLens 的财报分析助手。唯一任务是把给定的结构化事实改写成通顺的中文。
硬约束（违反即视为失败）：
1. 只能使用输入材料中的事实与数字，禁止补充外部信息。
2. 禁止生成输入材料中没有的数字。
3. 禁止投资建议类表述（买入/卖出/增持/减持/目标价/评级/建议关注等）。
4. 禁止预测股价或下一期业绩。5. 禁止对财务合规性下结论（不得说造假/舞弊/虚增）。
6. 只输出正文，不要标题、不要 markdown、不要解释你在做什么。
```

Prompt 里写"禁止"只算声明，**真正的约束在代码**：`guard_numbers()` 用事实集构造数字白名单，任何未出现过的数字整段丢弃；`guard_compliance()` 命中建议词即替换为〔已按合规规则删除〕。两条都在 `app.py` 里，可被测试直接调用（见测试用例 C3/C4）。

## 四、功能模块

| Tab | 做什么 | 防幻觉设计 |
|---|---|---|
| **一键摘要** | 6 个 KPI + 9 条结论，每条带置信度（高/中/低）与「查看原文」 | 无引文的结论**不生成**（不是标红，是不出现）；口径提示单独一行（如"现金流为负不等于经营恶化"） |
| **利润归因** | 把「利润增速 − 营收增速」的差值拆到可计算因子，并显示已解释比例 | **算不出来就说算不出来**：不用「本期÷(1+同比)」反推基期（实测差 43.3 万元）；毛利率未建卡 → 明确列「未覆盖 76.5%」 |
| **风险雷达** | 7 条规则，每条给公式、阈值、观测值、状态 | 只输出「命中·需人工复核 / 未见异常 / 无法判断 / 提示·已降级」，**不给分数、不给等级**；命中项并列公司自述原因；数据缺失判「无法判断」而非「未见异常」 |
| **智能问答** | 常见问题走确定性计算，其余走检索；答不出就拒答 | 答案中每个数字来自引文；拒答时给 3 条可答问题建议；买卖/目标价类提问直接拒答 |

## 六、完整闭环

| 维度 | 落点 |
|---|---|
| **数据** | 25 项指标全部带引文与字符偏移；缺失科目显式标注，不进结论 |
| **工具** | 5 个接口 + 1 个可选 LLM 通道；每个工具都有失败码与降级路径 |
| **状态** | 稿件日期 `as_of` 决定"当时可得信息"边界；上传后状态变为 `mixed`/`disclosure_unknown` 并在界面提示 |
| **反馈** | 置信度分档 + 口径提示 + 拒答建议 + 「哪串数字没过校验」的具体报错 |
| **人机协作** | AI 只改写措辞，判定权在规则；人点「查看原文」做最终采信；可导出底稿交合规复核 |
| **风险控制** | 数字白名单、合规词表、未来信息拦截、量级门禁（解析值异常直接丢弃）、无引文不生成 |
| **合规边界** | 不预测、不建议、不评级、不判造假；问答层对买卖类提问直接拒答（`ADVICE_Q`） |

## 七、失败条件与降级矩阵

**产品承诺：任何异常都表现为"明确的不可用"，而不是"看起来正常的结论"。**

| 失败条件 | 产品行为 | 为什么不能静默 |
|---|---|---|
| 稿件日期早于披露日 | 409 `FUTURE_INFO`，拦截不生成 | 会用"当时还不存在的信息"得出看似合理的结论 |
| 科目未抽取到（如 PDF 换行截断） | 该规则 `INSUFFICIENT`「无法判断」 | 标成「未见异常」等于把"没查到"说成"没问题" |
| 归因缺少两期原值 | 返回"无法计算"+原因，不输出百分比 | 用同比反推基期会引入数万元误差 |
| LLM 输出含无出处数字 | 整段丢弃 → 回退模板，并告警具体数字 | 数字错是这类产品最致命的错误 |
| LLM 输出含建议词 | 替换为〔已按合规规则删除〕并告知 | 无牌提供投资建议是合规红线 |
| LLM 超时 / 401 / 429 / 网络失败 | 降级模板结论 + 顶部横幅 | 不能让用户以为"AI 正常回答了" |
| PDF 是扫描件 / 加密 / 损坏 | 422 + 具体错误码 + 可操作建议 | 不做 OCR，硬解析出的乱码比失败更危险 |
| 提问超出披露范围 | 拒答 + 3 条可答问题建议 | 编一个答案比拒答伤害大 |
| 未收录的股票代码 | 404 `UNKNOWN_CODE` | 不能拿别的公司数据顶上 |

## 九、已知边界

| 边界 | 影响 | 当前处置 |
|---|---|---|
| 只覆盖 3 家公司、2026 三季报单期 | 无跨期趋势（如"应收增速连续三年高于营收"） | 明确写在此处，不假装有 |
| 毛利率、营业成本未建卡 | 归因最高只能解释 23.45% | 明确列「未覆盖」，不补一句"受益于产品结构优化" |
| 季报基期与营收同比不完全对齐 | R1/R2 的差值可能被放大 | 规则旁标注"仅作提示"，并把公司自述原因并列 |
| PDF 解析是"尽力而为" | 版式差异会导致科目抽取失败 | 量级门禁 + 失败即降级，不猜；新易盛营收被换行截断即为此例 |
| 不做 OCR | 扫描件不可用 | 返回 `NO_TEXT_LAYER` 并提示换可复制文本的版本 |
| 单期数据不年化 | 季节性会误导 | 不做年化，界面标注口径 |
| 数据 T+1 | 依赖公告披露 | 盘中不使用本产品 |
| 域名沿用工作区已发布应用标识 | URL 前缀为 `claimguard` | 产品本身是 FinLens；同一工作区只能有一个已发布应用，不影响功能 |

## 十、未做事项

1. **扶摇 / iFinD 实盘接入**——缺密钥，契约已预留（见 §5）。
2. **跨期与同业对比**——需要多期数据，当前只有单期；这是最有价值的下一步。
3. **披露后市场表现**——可接入扶摇 K 线，但容易被读成涨跌预测，需先定好呈现方式（只做"已发生的事实"，不做"因此会怎样"）。
4. **毛利率归因**——需要建「营业成本」事实卡，能把归因覆盖度从 23% 提到 80% 以上。
5. **多轮对话与长期记忆**——当前问答是单轮的，不保存上下文。
6. **演示视频**（可选材料）——未录制；主链路可现场走：选公司 → 三个 Tab → 点「查看原文」→ 提问 → 导出底稿，约 90 秒。

| 阶段 | 做什么 | 判定标准 |
|---|---|---|

## 附：7 条风险规则（可复算）

阈值是"筛选值得看一眼"的经验值，不是判定标准。

| 编号 | 名称 | 公式 | 阈值 | 数据缺失时 |
|---|---|---|---|---|
| R1 | 存货增速显著高于营收增速 | (存货期末/期初−1) − 营收同比 | > 20pct | 无法判断 |
| R2 | 应收增速显著高于营收增速 | (应收期末/期初−1) − 营收同比 | > 15pct | 无法判断 |
| R3 | 净利润未转化为现金 | 经营现金流净额 ÷ 归母净利润 | < 0.5 | 无法判断 |
| R4 | 利润依赖非经常性损益 | 扣非净利润 ÷ 归母净利润 | < 0.70 | 无法判断 |
| R5 | 商誉占净资产过高 | 商誉 ÷ 归母净资产 | > 30% | 无法判断 |
| R6 | 短期偿债压力 | 短期借款 ÷ 货币资金 | > 0.50 | 无法判断 |
| R7 | 研发投入强度下降 | 研发费用率（本期 − 上年同期） | < −1.0pct | 无法判断；**营收增速 > 40% 时降级为「提示」** |

R7 的降级条件来自一次真实误报：中际旭创研发费用同比 **+97.04%**，但营收同比 +178.13% 把费用率稀释到 2.68%（−1.10pct），规则字面成立、含义完全相反。**规则库必须被真实数据反复证伪才会收敛**，这一条写进产品而不是留在文档里。
